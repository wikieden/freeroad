# 两个独立 VPS 出口组

可选的 `clash-global-residential-extend-script.js` 在配置包含私有链式 provider 时生成两个手动策略组：

- `🖥️ 美国 VPS 出口`
- `🖥️ 美国 VPS 出口2`

两组引用相同的私有出口 provider，各自保存所选节点。更新订阅后，两组都从同一来源获取节点，无需维护第二份凭据。

例如原出口选择 VLESS，出口2 选择 Lychee，再让 Claude 选择原出口、OpenAI 选择出口2。Google、其他 AI、Steam、全局分流、国际媒体和未识别流量组也可选择出口2。两个出口只使用私有 provider，普通机场订阅仍通过国家组与出国前置选择。

两组共享现有的 `🛫 出国前置`；它们只分别选择出口节点，不提供两套独立前置。不要在前置中选择依赖该前置的链式节点，以免回环。

需要按具体网站分配时，在私有规则中把相应域名指向其中一个出口组，并放在更宽泛的分类规则之前。仅增加出口组不会自动创建网站规则。

Shadowrocket 私有配置可创建同名的两个 `select` 组，各自引用现有节点。实际链式由节点的 Proxy Pass 决定，复制策略组不会复制或修改节点的 Proxy Pass。

Clash Verge 更新配套全局扩展脚本；FlClash 拆分模式更新并重新绑定扩展 JS，或导入新生成的完整 YAML，二者选其一。Shadowrocket 重新导入生成的私有 conf 并使用配置。应用后检查各组保存的选择。

真实节点、账号和订阅仅保存在私有配置，不能提交到公开仓库。文件校验或云盘复制成功不代表客户端已经应用。

## 分组与直接节点

出国前置先列国家自动、国家全部节点和自建订阅组，再列具体节点。两个美国 VPS 出口都保留自建订阅自动/全部节点入口，同时直接提供私有原始节点与链式副本；同一节点在多个应用组中复用，不需要复制凭据。名称带“链式”的副本通过出国前置连接，原始副本单独保留。

Clash、FlClash 和 OpenClash 使用 HTTP provider，节点随订阅更新。可在私有 `freeroad-defaults` 中通过 `egress1-provider`、`egress2-provider` 指定两个出口的默认 provider；默认线路子组优先使用对应 provider 的首个节点。客户端保存过的选择可能覆盖此默认值。

Shadowrocket 的品牌自动/全部节点子组可使用忽略大小写的名称正则。父组需要同时显示子组和直接节点时，私有构建器支持 `shadowrocket-selection-rules.json`：指定名称快照文件、来源及匹配子组，将匹配节点追加到子组入口后。源文件不必手写每个节点，生成后的父组直接名单仍是快照。首页订阅更新只会更新动态子组；父组新增节点须刷新名称快照、重新生成并导入配置。

仅凭运营商关键字不能判定订阅来源。例如机场名称也可能含 Verizon。Clash 应按 provider 来源隔离；Shadowrocket 应使用明确品牌和命名边界，排除公告、套餐项和相似字符串。
